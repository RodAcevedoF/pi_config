# Personal Pi preferences

## Commits

- The user makes commits. Never commit, amend, stage, or unstage without their explicit authorization, ODD work units included; format rules below never authorize a commit. Preserve staged and unstaged work.
- Follow the repository's ticket prefix and convention; ask if unclear, never invent a ticket. Small, cohesive commits with short subjects such as `AT-098 fix: <message>` (an example ticket, not a default).
- When the repository allows it, detail related changes in this form:

```text
AT-098 fix:
- message
refactor:
- message
```

- No AI attribution: no `Co-authored-by`, `Generated by`, or agent signatures.

## Code comments

- Comment only what the code cannot explain itself: non-obvious intent, a constraint, or a workaround. One line, a few at most; never paragraphs.

## ODD

- `odd/` stays local and untracked; never force-add it.
